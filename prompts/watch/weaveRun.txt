Start with naama path={{DESIGN}} op=show, to see which domains exist and how the diagram is organised. Then op=add, one fact per line: `domain` before anything is placed in it, `type <Name> : <kind> @ <domain>` to place a type, `member`/`private` for its surface, `drop type <Name>` for a removal, `edge <A> -> <B> : <kind>` where the code makes a relation plain. The "code unit" named beside an added type is the assembly or package the file sits in — a hint about where it belongs, not the answer; the diagram's own domains win.

Every member row ends with an em dash and what it MUST DO. The signature is already in the code and can be re-read at any time; the intent is what a diagram exists to carry and the one thing nobody can recover later.

Leave off what does not belong on an architecture diagram — a test double, generated code, a shape with no behaviour — and say what you left off and why.

Finish with op=check, then op=render. NEVER add a type the delta does not name.
