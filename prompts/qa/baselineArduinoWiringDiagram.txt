This change touches physical pins (pinMode/digitalWrite/digitalRead/analogRead/analogWrite, or the evidence otherwise shows wiring is involved), so the reply owed to the user must EXPLAIN THE WIRING WITH A DIAGRAM, not prose describing which pin connects to what. The `arduino_diagram` tool renders wiring as a validated PlantUML diagram (a rectangle for the board with one nested rectangle per pin actually used, one rectangle per real component with a nested rectangle per leg, and labeled wire arrows between them), rendered to an editable SVG — check whether the artifacts or the final message actually reference that `.wiring.puml`/`.svg` output. A wall of text like "connect pin 13 to the resistor, then to the LED anode, then to ground" where a diagram was available and unused IS a failure: the tool exists precisely so wiring is shown, not narrated.
