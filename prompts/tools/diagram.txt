Explain a concept or an architecture with a picture: generate a validated PlantUML diagram, write it beside the work, render it and open it. Use it when a structure, flow or lifecycle is easier seen than read, or the operator asks for a diagram, schema or mindmap. A model writes this one, so it is checked only against the real renderer — that it PARSES, never that it is true of your code. For the types, members and assemblies a file really touches, use map_dependencies, which derives them and invents nothing. Pass `context` with facts already gathered; without them the picture is generic. kind=mindmap suits "explain this concept". NOT for Arduino wiring — use arduino_diagram.
